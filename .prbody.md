## What this is

The systemic half of #1269. That PR fixed **one** spec; this fixes the other twenty.

Of the 37 specs under `e2e/vrt/`, only **15** called `pinVrtFonts` / `awaitVrtFonts`. The rest navigated straight to `/rack` and screenshotted whatever face the capture machine resolved for the app's **generic** stacks — `--font-ui: 'Inter', system-ui, …` (Inter is the design font, but nothing in the app ships an `@font-face` for it) and `ui-monospace, monospace` for every knob / fader / port label.

**Why nothing noticed.** `document.fonts.ready` only tracks `@font-face` faces the *document* declares. System generic faces aren't in that set, so it resolves instantly and the fallback selection sails straight through. There is no symptom to spot: the baseline simply bakes in one machine's font choice, and every later run on a machine that chooses differently reads as a UI regression. The full root cause is already written up in `e2e/vrt/_fonts.ts` — this PR just applies it everywhere.

## A) The linux-deficit ratchet is blind to 62 of the 151 gaps

`vrt-meta.test.ts` ratchets `[...EXEMPT_BASELINE_PAIRS].filter(p => p.startsWith('linux/')).length ≤ 119`. That counts **one** of the **four** mechanisms actually in use:

1. **central `EXEMPT_BASELINE_PAIRS`** (`e2e/vrt/vrt-exemptions.ts`) — the only one counted. 119 `linux/*` entries.
2. **blanket `test.skip(VRT_PLATFORM === 'linux', …)`** — 8 spec files, **49** baselines. Invisible.
3. **per-spec LOCAL `EXEMPT_BASELINE_PAIRS`** const declared inside the spec — 4 spec files (`interactions`, `groups`, `dashboard`, `landing`), **10** baselines. Invisible — and note the trap: the local const is *named identically* to the central export, so a reader or a grep sees `EXEMPT_BASELINE_PAIRS.has(...)` with no signal that this one is a shadowing local the ratchet never reads.
4. **`darwinOnly: true` on a composite-scene def** (`vrt-composite-scenes.ts`) — **3** baselines. Invisible.

And the counted number is itself inflated. Breaking the 119 `linux/*` entries down by what they actually describe:

| | count | what it is |
|---|---:|---|
| real gap — darwin baseline exists, linux missing | **89** | the thing the ratchet is *for* |
| **both baselines committed, yet the pair still skips linux** | **15** | ⚠ see below |
| neither platform has a baseline | 5 | redundant with the module-level exemption (mirrorpool ×4, stages) |
| key **no spec ever queries** | 10 | `linux/toybox-*` — `vrt-toybox.spec.ts` never calls `.has()`; it blanket-skips linux and interpolates these keys only into the skip **message** |

**The 15 are paid-for coverage sitting dark.** Fifteen modules have a committed `vrt.spec.ts/linux/<m>.png` that is **never compared**, because a `linux/<m>` pair still `test.skip()`s them on the platform CI actually runs:

`macrooscillator`, `samsloop`, `scope`, `videoOut`, `audioOut`, `analogVco`, `lfo`, `feedback`, `lines`, `monoglitch`, `shapedramps`, `unityscalemathematik`, `vdelay`, `warrenspectrum`, `timelorde`

All fifteen PNGs verified present on disk; none is in `EXEMPT_FROM_VRT`. This interlocks with finding B — the pair suppresses the comparison, so nothing ever forces those baselines current, and **at least 7 of the 15** (`analogVco`, `lfo`, `macrooscillator`, `samsloop`, `timelorde`, `unityscalemathematik`, `warrenspectrum`) are rendering a stale palette. A lower bound only: the other eight paint their stripe from a class rather than an inline token, so the probe can't judge them. Skip the check → the baseline rots → nobody notices.

So the honest reading of the ratchet's 119 is **89 real, 30 that describe something else entirely, and 62 further gaps it structurally cannot see.** This is the CLAUDE.md "a gate that reads only one side of a two-sided contract" pattern — a ratchet whose input is one registry out of four.

*Why it is not fixed here:* draining the 15 is a deletion per module plus a re-run to confirm those baselines still match (several will not — see B), and moving the ~62 hidden declarations into the central set would **raise** a ceiling that may only shrink. Both need owner sign-off and their own PR.

One clarification, because the audit table and finding B read like a contradiction and are not: **coverage and currency are different properties.** All 48 strict modules have a baseline on both platforms — the gap count is genuinely zero. Whether each of those baselines still depicts what the app renders today is a separate question, and for 8 of them the answer is no. A gap audit counts files; it cannot see staleness.

## B) Baselines rendering a stale cable palette — in the REQUIRED lane

**#1159** (`e6b3814d`, 2026-07-22, *"cables match the mocks"*) recoloured the `--cable-*` tokens: audio → teal `#38d3c8`, video → violet `#b57bff`, gate → amber `#f2c14e`, cv → green `#7bd66a`, poly → pink `#ff7bc2`. Cards paint their top stripe as `<div class="stripe" style="background: var(--cable-X)">`, and the patch-panel jacks are token-driven too. **That PR regenerated only 9 baseline PNGs.**

A probe comparing each committed baseline's stripe against the token its own card declares:

- `vrt.spec.ts/darwin` — **23 of 52** token-pinned stripes off the current palette
- `vrt.spec.ts/linux` — **19 of 34** off, and **8 of those are inside the REQUIRED `STRICT_VRT_MODULES` set**: `adsr`, `cartesian`, `drumseqz`, `dx7`, `mixmstrs`, `score`, `sequencer`, `wavecel`

Verified by eye on `adsr`, magnified: the **linux** baseline stripe is salmon `#f87171` (the pre-#1159 gate colour), the **darwin** baseline is amber `#f2c14e` (the current token). Same card, same CSS, two palette generations. Confirmed by archaeology: `darwin/adsr.png` was last written by **#1159**, while `linux/adsr.png` was last written by **#1156** — which is *before* it.

**Why it is invisible, arithmetically.** The stripe is `height: 2px`. On a ~300 × 250 card that is ~600 px out of ~75,000 — **≈0.8 %**, under the **1 %** `maxDiffPixelRatio`. So the comparison **passes**; and because Playwright only rewrites a snapshot when the comparison **fails**, `--update-snapshots` refuses to repair it. The change is simultaneously invisible to the gate and unreachable by the regen.

**The 2026-07-31 tolerance tightening (#1267) does NOT catch this.** Going from `threshold 0.2 / ratio 0.05` to `0.1 / 0.01` moved the bar to 1 %, and a 2 px stripe is still under it. This is the A2/#1213 hole documented in CLAUDE.md, live in the **required** lane: the eight strict-lane linux baselines have been pinning a stale palette since 2026-07-22 while `vrt-strict` reports 48/48 green.

**The fix** (own PR, needs owner sign-off): **`git rm` the affected baselines and regenerate** — Playwright *always* writes a **missing** snapshot, which is the documented way around a passing-but-stale baseline — then one `vrt-update.yml -f platform=linux` dispatch. A cheap standing guard would be a pure-unit probe asserting each committed baseline's stripe row equals the `--cable-*` token its card declares: that reads the **pixel** side of the contract, which no current gate does.
