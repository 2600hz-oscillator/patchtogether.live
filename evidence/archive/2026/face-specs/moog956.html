§1 — WHAT THE MODULE IS FOR

The verb is PLAY. A horizontal resistive-ribbon clone (moogafakkin System 55): slide a finger → continuous V/oct pitch CV; a gate holds HIGH while touched; lifting off holds the last pitch (only the gate falls — the hardware wiper keeps its voltage). pitch = offset + pos × scale, the one formula, exported as ribbonToVOct() and shared by factory and card. Same UI-driven-CV-source family as joystick / gamepad.

§5 — THE FACE

face: {
  // RANK. `pos` first: it IS the instrument — the thing you play. The fader cell
  // is declared because nothing in a ParamDef separates “a position you throw”
  // from any other 0..1 scalar (the `noise`/`cameraInput` fader ruling, 2026-08-10).
  // `scale` before `offset`: span changes what a gesture MEANS mid-performance;
  // offset is set-and-forget tuning. `gate` last: normally played, not dialed.
  order: ['pos', 'scale', 'offset', 'gate'],
  paramCells: { pos: 'fader' },
  // `gate` is a press-and-hold, released-on-lift — the press-param pattern.
  // The factory reads it as a LEVEL (`value > 0.5`), and the surface must
  // PRESS and RELEASE, never latch: a latched gate would hold a note forever.
  momentary: ['gate'],
  // ONE band; four controls over one strip is a single idea. Far below
  // DOCK_TAB_MIN_BANDS (7) — no rail, and padding pages to reach one is refused.
  // No `pages`: the 4plexvid/rasterize unlabelled-band shape. A header would
  // restate the module name.
  glyph: 'none',          // §4 — no audio-typed output; anything else lies.
  extension: 'moog956',   // §6 — the ribbon body.
},

§5.2 Width — NOT earned

No picture, no scope, no XY pad. Four cells, one band, width: max-content. The plate should measure ≈ 4 columns + gaps; expect ZERO entry in FACE_WIDTH_EXEMPTIONS and near-zero slack in workflow-shell-faces.spec.ts’s content-vs-plate measurement.

§6 — THE BODY: face.extension: 'moog956', slot fullViewBody

§6.1 Why not a cell — the ladder, walked

rungrefusal
selector/toggle/filenothing here is a roster, a latch, or a file
the ranked fader itselfit survives and is the LANE answer — but a 16 px-wide vertical throw inverts the gesture (the hardware ribbon is horizontal, shoulder-width) and cannot express press-vs-slide: a fader drag cannot drop the gate on release. Parity of the two-param gesture (pos+gate in ONE pointer stroke) needs one surface that writes both
xyPadsarity is wrong: a pad binds TWO continuous params; gate is a momentary, not an axis. Declaring xyPads:[{x:'pos', y:'gate'}] would fail the lint’s continuous-axes check — correctly
PF-14 panel cella panel is a picture-you-edit INSIDE the band grid; the ribbon wants full plate width (a wide strip is the instrument’s ergonomics, cf. “a genuine earner is … a control that appears in one mode only” — this is a control whose PRECISION is its width)
fullViewBodyTAKEN — the module’s own playable strip at the head of the dock view, frogger/pong’s slot with a control instead of a game

§6.2 The component

$lib/ui/modules/moog956/shell-extension.ts default-exporting { fullViewBody: Moog956RibbonBody }. The body: a full-width ribbon strip (the card’s pointer logic, verbatim — capture, hold-on-release, clamp via the def’s exported clampRibbon), role="slider", aria-label="Ribbon", aria-valuemin/max/now + aria-valuetext carrying “+7.2 st”. Writes pos/gate through the engine param path (same seam the cells use). It does NOT paint the bands’ cells — they render below, untouched (the seam’s own rule: a body is a complement, never a replacement — the warrensspectrum failure).
