SCREEN OFF SKIPS THE BLIT, NEVER THE ADVANCE — and that inversion is module-specific. This module’s painter runs INSIDE read('imageData') (advanceOncePerFrame), so when nothing downstream is patched, this body’s loop is the only thing advancing the raster. Stopping it on collapse would freeze the module itself — the #1720/#1721 class the owner’s “it KEEPS RENDERING while OFF” floor exists to prevent. It is also the cheap half to keep: the advance writes ~800 pixels; the blit is a 1024×768 → 480×360 scale-draw. ⚠ A sibling body copying the raw requestAnimationFrame without this inversion ships an ungated full-canvas redraw — dockscope’s body correctly uses onMeterFrame instead.
⚠ SCAN IS RANKED LAST, AND THE RANK ENCODES AN OPEN DEFECT. RasterPainter.paint() re-seats the running cursor only when Math.floor(params.cursor) differs from the last value it saw (rasterize-draw.ts:98-105). So re-selecting a value the knob already shows is a no-op, and the number diverges permanently from the real scan position. On top of that the range is VIDEO_RES.width × VIDEO_RES.height pixels and the finest gesture moves ~39 of them — a control declared in px that cannot address a pixel. The def leaves a deliberate pointer so the rank is re-decided rather than inherited (rasterize.ts:209-218). #2000, open.
