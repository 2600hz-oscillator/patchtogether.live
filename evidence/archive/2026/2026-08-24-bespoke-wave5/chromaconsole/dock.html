The two marks on the right plate, and why only one is real

markwhat it is
diffusion, violet ring Real, and part of the design. A STALE slot — a saved assignment that no longer resolves. The card prints “N slot(s) point at controls this device no longer has” (:221-223); the face marks the offending CELLS. Strictly better: the card says how many, the face says which. status.staleSlots already names them.
bypass, red ring Not part of the design — it is a DEFECT drawn so you can see it. Ten of the pedal’s controls are role: 'enum'; the card renders those as a Segmented over named ranges (:259-267). A face cannot: face.paramCells has no segmented kind, and these params cannot carry an options roster because a roster must be TOTAL over 0..127. So a slot assigned to BYPASS becomes a smooth dial over a 2-state control — the moog962 inertness class from the opposite direction. spec.md §5.1.
⚠ Size the two blockers TOGETHER. A per-node CAPTION and a per-node cell KIND are one capability wearing two hats. Solving only the caption ships eight correctly-labelled knobs, ten of which are the wrong primitive.

Width — 340 px, and the mode is what keeps it there

Card: 360 px (:320), and its comment says why — “2 × the 180px rack tile, so the card lands on the grid”. That is a rack-geometry constant, not a content measurement.

Content is eight knob columns. Measured off the live dock (20 faces, 104 cells, a 1220 px pane) knob columns are 40–68.8 px. Eight in a row is ~600 px; 4×2 is ~300, which is the grid the card’s own knobLabel() doc already assumes (“short enough for a 4-across grid cell”).

Why ASSIGN is a MODE and not eight resting dropdowns

The card renders eight <select>s permanently, one above each knob (:238-252) — eight dropdowns of chrome for a setting changed rarely, doubling the plate’s height.

Three independent reasons for the mode, and it matters that they are independent:

1Compact. Owner: “screen real estate is expensive!” Resting height roughly halves.
2“A control that appears in one mode only” is one of the four NAMED genuine width earners. Pickers need ~200 px each for a grouped roster of 27; knobs need ~68. The mode is what lets the resting plate be narrow and the editing view be wide — the earner is spent only while earning.
3It matches the module’s own model: docs.explanation treats assignment as a setup act and slot-turning as the performance act.
⚠ The mode’s state is COMPONENT state, not node.data — deliberately against the SCREEN-toggle pattern. previewCollapsed persists because it is a VIEW PREFERENCE; an assign mode is a transient EDITING state, and persisting it would reopen the editor on every load and sync one collaborator’s editing into another’s performance view. The #1531/#1574/#1583 unmount class makes component state the wrong default, so choosing it needs the argument written down.

Eight identical instances — and #2181 resolves the OTHER way here

CLAUDE.md: “A family key is ONE cell for ALL instances.” That is right when the instances are interchangeable — mixmstrs drops its 1LO…8LO captions because a LOW heading already conveys them.

These eight are not interchangeable, and that is the whole module. Slot 3 is TIME today and MIX tomorrow. The caption is the only thing separating eight identical knobs — the tidyVco A/D/S/R case, which CLAUDE.md rules STAYS. face.bareCells must NOT be declared here.

⚠ Which is exactly why the blocker blocks: the one thing the ruling says must stay is the one thing a face cell cannot render.

No rail — and the control-heavy ruling does not apply

That ruling is about “lots of controls of DIFFERENT types” — backdraft’s eight semantic pages. This is eight controls of ONE type. Splitting them would be padding pages to force a rail, named as an anti-pattern in the same ruling. One band is correct: the owner ruled ruttetra untabbed at twelve params in the same breath as ruling spirographs tabbed at three.
