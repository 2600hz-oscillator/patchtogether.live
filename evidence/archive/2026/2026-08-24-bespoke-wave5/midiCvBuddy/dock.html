A wrong-channel keyboard is still diagnosable (dot dark); a wrong-OCTAVE keyboard is not. That narrowing is the ruling’s intended trade, and spec.md §6.1 states it rather than letting the coverage quietly lapse.

Width — 300 px, and nothing earns more

The card measures 220 px with a 192 px control column (MidiCvBuddyCard.svelte:203-205). The face is the same four rows; the extra ~80 px is headroom for a long Windows port name, which duplicates its device name in the WinMM roster.

No live picture, no scope trace, no video preview, no XY pad. Nothing earns width, so face-width-source.test.ts gets no exemption entry — which is the point.

Speakable and assertable, never painted. Every spec proving a face tracks the graph already reads aria-valuetext, so no assertion had to be weakened to survive the removal.

PRIO is a segmented, not a dial

Three named states. A 2..3 discrete param drawn as a KNOB has two reachable positions across the dial’s whole travel and quantises back to where it started — moog962 shipped that way and faces-parity failed it twice. PRIO is not a param at all here, but the same reasoning picks the primitive.

The glyph is 'none', and it is forced

Outputs are cv / gate / cv — no audio port. primaryAudioOutPortId matches type === 'audio', so any other literal resolves to {kind:'static'} and the dead-glyph clause reddens unconditionally.

The glance a player actually wants — is a keyboard bound, and is it sending? — is a BINDING STATE plus an EVENT RATE, and all five VALID_GLYPHS members describe a continuous audio quantity. This spec does not invent a sixth on a module PR.
