the precursor, and it is four lines

The rule already exists and already states the reasoning:

legacy-fallback.ts:229-231
export function dockRailRendersFace(i: DockRailRenderInput): boolean {
  return i.shellFaces && i.pinned && i.migrated;
}

legacy-fallback.ts:186-188   (its own header)
  "a PINNED occupant is canvas-hidden ... so it has NO lane tile, NO EXPAND pill
   and no route to DockFullView. The tray is its ONLY surface, and it is
   therefore the only place its face can appear."

Canvas.svelte:2043 calls it for the drawer rail. AudioIoSurface never does. Thread shellFaces and migrated down from WorkflowTopbar and call it once per column with pinned: true.

⚠ Do not re-derive ?shell=legacy or migrated() inside the component. The rule is pure and injected precisely so those are read in ONE place.

⚠ Thread it for BOTH columns. A rule applied to one of two identical adjacent occupants makes the panel's behaviour depend on which module someone promoted last.

and two independent mechanisms would hide it

1 — the prop is missing, so the panel cannot render a face at all.

2 — the one VRT scene watching this panel is on the legacy path. workflow-audio-io-composite.spec.ts:53 is page.goto('/rack?shell=legacy'). Under ?shell=legacy, shellFaces is false, so the rule is false even after the prop is threaded. That scene can never show a face here.

⚠ And that scene exists for this panel — its header cites the owner report "this should have been caught with vrt analysis". It is the panel's dedicated watcher, and it watches the arm promotion does not touch.

The tree already names this class, for the neighbouring surface (legacy-fallback.ts:200-204): the three shipped drawer specs "both drive /rack?shell=legacy, so they exercise the false arm forever." The audio I/O panel has the identical condition and no such warning.
