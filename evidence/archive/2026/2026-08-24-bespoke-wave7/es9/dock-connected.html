What is still NOT painted, in the state that most wants to paint

device name → aria-label 48 kHz → aria-label 16×16 → aria-label rtt 4.2 ms → aria-label 3 underruns → aria-label jacks 3,4,7,8 → per-cell aria-valuetext

Six derived quantities, zero text nodes. StatusLed has no value prop and its caption is static by contract, so a caller cannot smuggle a measurement through lit ? 'XRUN 3' : 'OK' — the source gate denies that at the call site.

The claim mark is a MARK, and the distinction is load-bearing

Wave 5 §2.1 settled it: the ruling is about TEXT. A non-text indicator carrying the same information as a forbidden readout is fine; a "compact" or abbreviated version of the readout is not — "there but hidden" was refused by name. The test is whether a reader has to read anything. Here they do not: a tinted outline and a notch.

One jack set to a NON-DEFAULT class, deliberately

OUT 1 shows CV and IN 2/3 show PIT/GAT so the option NAME is visible doing its job. That name is the only text a class cell ever paints: paintsReadout is true for a bare options roster with no declared format, and it renders the NAME, never the number. A face that showed 2.00 under a class dial is the exact decimal the 2026-08-17 ruling deleted.

⚠ And the class change may not reach the hardware

Setting OUT 3 to pitch should switch the bridge's failure policy for that jack from FADE to HOLD (es9.ts:140-149). On main the only thing that pushes that is Es9Card.svelte:89 — a card the default shell never mounts — and the CV-Buddy janitor never pushes it at all. This mock draws the intended behaviour; the tree does not implement it. spec.md §11 is the precursor that makes the picture true.
