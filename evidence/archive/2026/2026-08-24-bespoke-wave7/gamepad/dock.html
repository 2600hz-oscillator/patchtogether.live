What stayed, and why

The twelve LED captions. tidyVco's A/D/S/R argument at three times the scale — they are the only thing separating twelve identical tiles. They are read from GAMEPAD_OUTPUTS so a def-side label edit propagates, which is the one-source rule applied to captions.

SLOT 0 1 2 3 — option NAMES inside the control that selects them, at the strongest possible position: they are the segmented cell's own option labels.

NXT Gladiator in the preset dropdown — an option name inside the control that selects it. The settled discriminator, applied.

The speakable leg BITES here

The naive port writes aria-label={btn.label} beside >{btn.label}< on twelve tiles — exactly what face-rack-status-source.test.ts:826-860 refuses. So:

aria-label = “A — gate output, driven by button 0. Right-click to rebind, alt-click to reset.”

which is the removed hover string plus the removed mark, made speakable and permanent.

Nothing to connect

The Gamepad API has no permission prompt and no events this module uses — “the Gamepad API has no events, so an armed listener must poll”. The protocol is a gesture gate: press a button on the hardware. There is no in-page affordance that can cause it, so the copy is an instruction, not a button.

⚠ And the poll that drives the audio lives in the FACTORY, not the card (gamepad.ts:1268-1288, torn down in dispose()). Collapse the card and every output keeps running. No status registry is needed and none should be built — a copy would be a second owner of state the engine already owns.
