⚠ THE MEASUREMENT, FIRST. The lane width function takes a TYPE and has no nodeId at all — and the uniformity is quoted in the source as the owner's own premise, not as an oversight: 
// Canvas.svelte:641-652
/** A module TYPE's rendered card WIDTH in flow-space px. Under the `?shell=1`
 *  preview a shell/placeholder tile is the UNIFORM SHELL_TILE_W (every module the
 *  SAME width — the owner "same-size horizontally" premise) … */
function wcolCardWidthPx(type: string): number {
  if (shellFaces && !NON_SHELL_LANE_TYPES.has(type)) return SHELL_TILE_W;   // = 192
  return (rackSizeByType[type]?.hp ?? 1) * RACK_UNIT;
}
So a per-node lane width would be BOTH a missing platform parameter AND a reversal of a stated owner premise for all ~200 modules. Neither is an agent's call, so neither is proposed.

Its body has no resize handle, sizes itself width:100%; min-width:260px; flex:1 1 auto with the comment "a live picture is the canonical thing that EARNS width", and carries fullscreen + full frame + detach + present instead.

the four routes, mapped to what a player did

what the resize was FORon the face
make ONE videobox big enough to watch FULL FRAME (node.data.fullFrame — the SAME key) and FULLSCREEN with the display picker. Both already on the card, both ported
make the DOCK preview a comfortable size a body corner-resize over resizedWidth/resizedHeight — five existing adopters (ruttetra, bentbox, b3ntb0x, milkdrop, graphicEq)
put SEVERAL clips on screen at once, at chosen sizes DETACH — its own window, any size, any display. ⚠ Strictly better than 360 px tiles inside a rack canvas

What genuinely changes is the geometry, not the capability: several videoboxes tiled inside the rack canvas at per-node sizes is not expressible, because the rack canvas is uniform-tile by ruling for every module. videoOut inherited that first.

⚠ DETACH and PRESENT are ADDITIONS — say so in the PR body

videobox's card has fullscreen and full frame today; it has no detach and no present. Adding an affordance a module never had is normally out of scope for a face PR.

Here it IS the parity argument, and the components are already written and already shipped on a sibling (use-present.svelte is node-keyed via node-present-registry; detached-display.ts is shared). Do not let it read as scope creep discovered later.

⚠ the DOCS promise the surface promotion removes

videobox.ts:143 currently says "The card is drag-resizable from the bottom-right corner (whole-rack-unit tiles, default and minimum 360x360) so several videoboxes can be tiled into a wall of TVs; size persists on the node and syncs to peers."

Leaving it is the modtris/score class wave 5 named: documentation promising behaviour that is not there, on a module in STRICT_DOCS, invisible to module-docs-lint because that gate reads the DEF. Rewrite it to name the four routes. docs is hash-transparent, so the rewrite is free.
