What this mock is asserting

  • The well is DOM, at both tiers. 64 <span>s in a CSS grid, 1fr columns, aspect-ratio: 1 / 1, a 1px gap, and the only px dimension on the container (--well-px: 104 tile / 176 dock). There is no canvas, so the modtris/skifree DPR blit rules have no subject here — the four properties above are the DOM equivalents. Converting to a canvas would delete 64 data-testids plus data-piece and would import a bug class this module is currently immune to.
  • The scene column is hardware order, verbatim. Indices 0–7 top to bottom; 1 and 2 are dead spacers that still occupy their rows. The captions are the card's own (reset / drop / rot ← / rot → / move ← / move →) and each live button carries its Scene button N — … title, which is how the mapping stays learnable with no hardware attached.
  • Compact always, decimals gone. No knob shows a number; the value is the pointer angle. No counters (lines, spawns, notesFired are all in the snapshot and all deliberately unrendered — the card does not show them either). No hero readout strip.
  • The only prose is device state. Six strings from seqtrisStatusMessage(), a pure unit-tested function. Kept 1:1; the idle sentence is the one borderline case and is logged as an owner question rather than trimmed.
  • SCREEN is dock-only and the tile honours it. One node.data.previewCollapsed boolean, written once per click. The switch overlays the well's corner so it costs zero layout height.
  • No keyboard-nav affordance is added. Standing owner ruling.

What is deliberately NOT here

  • No NEXT-piece preview. The card has none and SeqtrisSnapshot exposes no next field. That is modtris' strip, not seqtris'.
  • No CONNECT or scene column in the lane tile. The ~192 px tile cannot carry them under the io-spec-consistency bounds gate. Recommended default, and the one genuine geometry loss against ?shell=legacy — it is one click deep. Owner question 1.
  • No seqtris-card-${id} root. The shell owns the plate. Measured consumer count: zero.
