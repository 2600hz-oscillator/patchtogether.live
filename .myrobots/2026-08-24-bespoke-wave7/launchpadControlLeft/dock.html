Two ranked cells, and why not four

SINGLE and PAIR rank. Both are always-meaningful gestures with a fixed label — the only thing ShellActionCell can express.

BIND does not rank. It is a no-op when there is no clip-player (:112-113), and an action cell has no disabled. A ranked BIND would be a control that looks alive and isn't, in the state a fresh rack is always in. VIEW does not rank either: the segment only exists in single mode, so a selector cell would have an empty roster in pair mode. Both live in the body, where ordinary Svelte keeps the card's own conditions.

⚠ With params: [], every key face.order can hold is a non-param key — so all four affordances are declared as one-member controlFamilies. That is matrixMix's route verbatim, and it is #2181's construct used for the opposite reason: not to collapse a bank, but because there is nothing else a zero-param face can rank.

⚠ The card has ZERO surface coverage

grep -rln "launchpad-control-" e2e/ packages/web/src returns one file: the card itself. Meanwhile 6,278 lines of unit tests and five e2e specs sit beneath it — and all five run only under ?shell=legacy via the rack fixture, driving __launchpadTestInstall / __launchpadSim globals that Canvas.svelte installs.

So promotion cannot break the launchpad, and nothing would notice if the face were broken. The face PR owes this module's first surface e2e — and it is the exact inverse of the sibling, whose one spec is default-shell only and does break.
