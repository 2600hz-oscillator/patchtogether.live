the same canvas, the same seam — nothing on the plate switched mode

Every string on this canvas is the MODULE'S ARTWORK, not the face's chrome. Wave 5 GAMES.md:59-65 settled the class; this is its strongest instance, because the pixels are a replica of a physical object rather than a representation a module chose to draw. Deleting the readouts would not remove a readout from the product — the OLED still paints them — it would only break the one-seam guarantee. And no gate sees any of it: face-resting-text-source reads face FIELDS and is blind to a body's markup by its own admission; canvas pixels are invisible to every source gate in the tree. The enforcement is the dock VRT baseline and a human reading it.

⚠ the replica paints another node

Eight strips of name + bar + formatted readout, belonging to whichever module the selected lane is focused on. That is stated as the reason the module is VRT-exempt today: "the push-card preview canvas renders whatever module happens to be in lane 1, so the card face is patch-dependent" (vrt-exemptions.ts:687).

Which is why the drain is a scene decision, not a policy decision. A scene that spawns push2Control alone has an empty lane 1 and paints the deterministic empty card — state 1's picture. If that proves unstable, the answer is a NAMED FACES_WITHOUT_SCENES entry (_shell-faces.ts:3391), never a silent absence and never a re-exemption.

the drain, and the file count

Two anchored deletions — EXEMPT_FROM_VRT:687 and ALLOWED_PERMANENT_EXEMPT:1214. The second set is anchored in both directions (:1197-1199), so leaving the name behind is RED, not stale.

Predict 3 files, not 2. vrt.spec.ts:52 builds COVERED_MODULES as REGISTRY.filter(m => !(m.type in EXEMPT_FROM_VRT)), so the drain also enrols the legacy card. midiclock's three committed PNGs are the arithmetic, verified: vrt.spec.ts/midiclock.png + face-midiclock-compact.png + face-midiclock-dock.png.

the 2-D context is a scheduling fact

webgl-attest-lib.ts:267-272 walks all of lib/ui/modules and enrols any .svelte whose stripped source matches /getContext\(\s*['"`]webgl2?['"`]/ (:40). A new push2Control/Push2SurfaceBody.svelte is walked; it stays out of the basis only because its context is '2d'.

So attest cost is ZERO — and "keep it 2-D" belongs in the body's why, where the next author reads it before reaching for a shader. matrixMix's entry makes the identical argument from the other direction.

⚠ a FIFTH state location

Waves 3–6 tracked a .data census with four states. This module is a fifth: none of its state is in the document. The lane select is localStorage (push2-control.svelte.ts:154-157, :449); the binding, shift, legend and focus are module-level runes (:126-146); mutateNode appears zero times.

And it is correct, not sloppy. Two collaborators on one rack each have their own Push on their own lane — syncing selectedChannel would make one player's button move the other player's hardware screen. That is what forces the lane select into the body rather than a family cell (a family is a node.data-backed picker), and it is a third independent reason the env-for-selectors ask would not have helped: no engine handle of any shape reaches localStorage.
