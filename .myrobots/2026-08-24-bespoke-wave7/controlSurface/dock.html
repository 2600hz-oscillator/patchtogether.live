A user-typed name is a CAPTION — settled

The ruling ranges over a text's ROLE and POSITION, never its author. SQUELCH above was typed by the player; it sits inside the control it names and disambiguates it from its neighbour, which is the caption role exactly.

The alternative rule has a shipped counter-example: a user-renamed MODULE name is permitted in every faceplate's title bar on ~300 modules. A user-typed control name is permitted as the control caption by the identical argument, one level down.

The sentence is speakable, not painted

face-rack-status-source.test.ts:826-860 refuses an aria-label={E} whose same expression is also a text node. So the caption stays {c.label} and the accessible name is a different string:

aria-label = “ATTACK on ADSR 1 — proxied control; turning it writes the source module's live parameter. Right-click to remove it from this surface.”

⚠ The gate's predicate is expression identity, so it cannot catch a spelled-out duplicate. The compliance argument rests on the sentence genuinely differing, and only the dock PNG and a human can see that.

The colour stripe is PASSTHROUGH

Each stripe is a live read of the SOURCE module's control colour through resolveControlColor(sourceNode) — never a stored copy, so the same control shows the same colour everywhere it appears. It is a non-text mark and the ruling does not reach it.
