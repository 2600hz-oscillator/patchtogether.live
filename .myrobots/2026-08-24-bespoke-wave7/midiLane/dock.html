Width — nothing is earned, and nothing is asked for

The card is 230 px (:290) with a 42 px caption column (:321-327). The face is the same controls in five bands; no live picture, no scope trace, no video preview, no XY pad. face.hero is not declared and face-width-source.test.ts gets no entry — which is the point.

⚠ One measured caution: the DEVICE <select> in the body needs a max-width the way the shipped one does (MidiclockDeviceBody.svelte's 190px), because a Windows WinMM roster duplicates its device names. A body that lets one option set the plate width is a face whose width is decided by someone else's driver.

Five bands. No tab rail.

DOCK_TAB_MIN_BANDS is 7 and face.tabbed is owner-instruction-only. Five honest bands render as a column, and that is correct. Nothing is padded to reach a rail. ⚠ The fifth band exists only because bandFocus splits mono off voice — and bandFocus reads a PARAM, which is the second independent reason mode must migrate out of node.data.

⚠ The MIDI note NUMBER is a real narrowing: drum programmers think in numbers, and the def itself defaults to "GM kick = 36". It survives in each option's title and in aria-valuetext, and the family's docs.controls prose names the GM mapping. Stated rather than allowed to lapse.

The activity lamp is a LAMP, and it must not be wired to lastNote

MidiLaneCardState.lastNote is documented as "Last note received on the lane (MIDI int) for the readout" (midi-lane.ts:198-199) — i.e. possibly a LATCHED value. A lamp bound to it would latch ON after the first note and never go dark, which is a lamp that says nothing. Bind it to the HELD-KEY STACK, the way midiOutBuddy's dot uses activeNote !== null. Flagged in spec.md §6.1 as a real instrument hazard rather than assumed away.

The drain, in one line

Nothing is needed — it is already drainable, and its own exemption text says so. vrt-exemptions.ts:769-774: "the rich card UI … only appears AFTER Connect … the pre-Connect state is just the "Connect MIDI…" button + hint." That second clause is the exit condition and the harness only ever sees the second clause. Same argument, same four-entry block, as the midiclock drain.
