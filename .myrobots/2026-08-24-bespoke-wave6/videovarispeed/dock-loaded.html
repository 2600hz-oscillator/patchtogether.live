why the CROP is BODY markup and not a PANEL

⚠ Not twotracks' per-frame-read discriminator — the rect really is on node.data.crop, so a panel probe could read it cleanly. The reason is registration:

a crop box is drawn in the coordinate space of the frame. A panel is a separate box in a band row, so it would have to blit a second copy of the same node to have anything to draw the rectangle over. The overlay must sit on the pixels it crops.

The platform already agrees where it has been asked: quadralogical declares face.xyPads[0].surface:'body' for the same reason. Crop needs no declaration at all — it is {active,x,y,w} on node.data, not two params.

⚠ this module is UNCONDITIONALLY pull-exempt

isPullExempt returns true on a non-empty audioSources map (engine.ts:1171), and the factory installs two silent ConstantSourceNodes at construction (videovarispeed.ts:394-406) — before any file is loaded.

So the markWatched-while-SCREEN-OFF argument twenty-eight roster entries carry does not apply on its usual grounds. The body still marks — because the exemption evaporates in an audio-less boot, which is the environment the gates run in. Write the honest reason, not the copied one.
