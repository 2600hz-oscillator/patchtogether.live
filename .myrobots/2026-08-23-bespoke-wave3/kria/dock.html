THREE BANDS, UNTABBED — and that is a decision, not an omission. Mirroring Kria's hardware pages (TRIG / NOTE / OCT / DUR / PRB / GLD / RAT / LOOP / TIME / DIRECTION / SCALE / PATTERN) would clear DOCK_TAB_MIN_BANDS = 7 comfortably and produce a rail. That would be padding. The per-step lanes are not bands — they are which lane the grid is editing, one selection. LOOP and TIME are the same idea twice, so they are clusters at ~14 px, not pages at ~81 px. face.tabbed is owner-instruction-only; if a rail is wanted here, that is a threshold conversation.

the accessible names — the part the card gets wrong

The card's every cell is aria-label={`step ${step} row ${row}`} (KriaCard.svelte:325) — a bare coordinate, page-invariant and value-free. On a face that matters more than anywhere else in the wave: the plate paints no derived state, so aria-valuetext is the only place the sequencer's state exists in a readable form.

the rosters already exist

Every selector above reads a symbol kria-types.ts already exports:

⚠ Import them, never re-type them. kria joins RANGE_BOUND_CARDS when this PR touches it.

Div is a roster, not a range

KRIA_TIME_DIVISIONS = [1,2,3,4,6,8,12,16] — eight irregular values. A knob would let a user land between two legal divisions. A selector cannot.

Same argument for Start and Length: a knob over sixteen integers has no landmark at any position; a roster names the step.

Root is note names, not MIDI

The stored value is MIDI (48 = C3). A face that made a user pick 48 would be a worse instrument than the hardware. The roster is note names; the cell writes the int.

the selection lives in node.data

Not component $state. Three independent reasons, any one sufficient:

1. Every cell above except Run and BPM is "…of the selected track", and a cell's value(node) receives only the node.

2. The component unmounts on dock collapse and LRU eviction — the #1531 / #1574 / #1583 class.

3. It makes the cells and the body agree by construction rather than by a prop contract nobody gates.

the GRID button is narrower than wave 1's gap

Wave 1's finding #3 is about hardware egress — proving a SysEx preset arrived. This button proves only binding, and binding is already in the graph (boundKriaNode()).

So: kind: 'action', mode: 'trigger', a data probe — the kind the registry says to prefer. ⚠ And it records delivered: false rather than dropping it when WebSerial is unavailable.

no lane picture — a third distinct mechanism

Outputs are pitch* / gate*, no audio, so primaryAudioOutPortId is null and every literal falls to dead static. Mechanically protected.

⚠ And #2160 would not rescue it: with no nodeId on ShellExtensionGlyphProps every kria would draw the same sixteen steps — and the sequence IS the module. Worse, kria needs strictly more than nodeId: the picture depends on the selected track and lane too.
