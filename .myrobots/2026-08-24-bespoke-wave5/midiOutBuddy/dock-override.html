The violet outline is IDENTICAL in both panels. That is the point — the signal is already non-text and already the e2e’s source of truth. Only the badge and the NOTE row are gone.
⚠ WHAT NARROWS, said plainly. The badge named the two numbers; the outline says only that they differ. The numbers are in aria-valuetext — speakable, assertable, unpainted — so a sighted player now sees “something is off-lane” and must open the cell to learn “what”. That is a real reduction in at-rest information and it is the ruling’s intended trade, not an oversight. CLAUDE.md requires it be named rather than allowed to lapse quietly.

⚠ And the LANE tile loses the signal unless one CSS rule is added

The outline is styled on .mod-card[data-ch-override='true'] (:258-259). After promotion there is no .mod-card — a ModuleShell tile has no such rule, so the divergent-route signal would silently vanish from the LANE while surviving in the dock. One shell CSS rule, keyed on the same attribute, is the fix. It is a defect that promotion CREATES, which is a more dangerous category than one it inherits, because it does not exist until the PR that must also fix it. spec.md D3.

Why this state exists at all

midi-out-buddy.ts:217-229 spends thirteen lines on it. data.channel is the channel-column MEMBERSHIP scalar and is not this module’s to write — the column reconciler prunes and re-adopts nodes by it, “which also re-plans the lane’s clip note-tap edges and re-binds the automation lane.”

So a card that wrote data.channel to set its MIDI output channel was silently reassigning its lane and losing its clip assignment on every change (#1168). The MIDI-out channel therefore lives on its own key, and the two are allowed to disagree forever.

Why CH cannot be a param

this control
reads frommidiOutChannel ?? channel ?? 1
writes tomidiOutChannel ONLY
carries an invariantisMidiOutChannelOverridden()

A ParamDef has one storage location. This has a read key, a write key, a fallback chain and an invariant. It is not a param and must not be made one. The fullViewBody is not a convenience here — it is the only shape that fits.

Where the numbers went

CH cell aria-valuetext = "channel 9; this module's lane is 3"

⚠ Verify the spec reads the ATTRIBUTE

:189-190 claims data-ch-override is “one source of truth” for both the styling and the e2e. If any assertion in workflow-channel-columns.spec.ts reads the badge TEXT instead, the removal breaks it. Check the spec file, not the comment — a comment does not gate, and this is the one place in this module where the two could have drifted.
