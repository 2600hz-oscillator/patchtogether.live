The DOT is not a readout

The ruling’s own wording is “a value, a measurement, a state word or a sentence has no place.” A lit/unlit mark is none of those, carries no text, and is what [data-ch-override]’s outline is too. Meaning without printing it is an established idiom here — rear-direction.ts carries port DIRECTION on four non-colour channels for the same reason.

Do not over-apply it. A dot carrying the same information as a forbidden readout is fine; an abbreviated readout is not — “there but hidden” was refused by name. The test is whether a reader has to read anything.

⚠ The affordance the STOP-2 grep cannot see

MidiOutBuddyCard.svelte:162-165 is an $effect that keeps the engine’s send-channel in step with the derived effective channel, “so a module that has NOT been overridden still follows its lane when it is moved between columns.”

Promotion deletes the card, and that effect with it. A module dragged between channel columns would silently stop following its lane. The skill’s STOP-2 grep looks for <button, <select, <input… — it is structurally blind to a component-lifecycle side effect the card performs on the user’s behalf.

⚠ Grep for $effect( and onMount( too, on every module in this cohort. spec.md §3.1 carries the fix — move the reconciliation into the engine factory, which already owns setChannel and already reads node.data. Putting the effect in the fullViewBody instead is rejected: a body is dock-only, so correctness would depend on a dock being open.
