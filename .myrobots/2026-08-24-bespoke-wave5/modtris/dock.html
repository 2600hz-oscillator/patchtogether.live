MODTRIS — dock faceplate · the well

Spec and mockup only; nothing here is implemented. One band, two faders and a fullViewBody. MODTRIS is a gate-driven ACCUMULATOR whose output rate is a function of how well the patch is playing — nothing else in the rack has a stack that remembers, so the same input pattern produces a different output rate ten seconds later.

controls & primitives

keyprimitive & why
gravityBpmrank 1 · paramCells:'fader', DECLARED. The module's TEMPO, and on a gate-output module that is rank 1 by definition. ⚠ AND it is the only param read EVERY STEP (modtris-state.ts:407), so it acts on the next frame. On pong “tempo” and “acts now” were split across two params and the spec had to choose; here they are the SAME param — the least contestable rank in the wave.
levelSteprank 2 of 2 · fader. ⚠ Not a runner-up on merit — it does nothing. If §13.1 WIRES it, the rank is right (a difficulty ramp changes rate over time and a rack cares about rate). If §13.1 DELETES it, this row disappears and modtris becomes a one-param face. The rank is not defensible until that is answered, and saying so is more useful than defending a rank for a dead control.
—⚠ NOT warped-fader. Checked deliberately: that cell is for a param whose CARD converts at the boundary. ModtrisCard does not convert — it passes min/max/curve straight through, as literals rather than the def's symbols, which is a ONE-SOURCE defect and not a warp. The warped-fader cell would encode a map that does not exist.
freezeNEW · noUserControl, writer:'internal'. Required by the VRT seam and nothing else — and required because the game clock is a Web Worker interval that an audio suspend cannot stop.
—⚠ No RESET / NEW GAME. modtris has no restart input at all, unlike frogger's start_gate; the stepper re-inits itself on overfill, so the game recovers but the player cannot choose to. Refused because it does not exist on the card either — it needs an input port (a contract change) or an ACTION cell with an AUDITION-LEDGER probe.
