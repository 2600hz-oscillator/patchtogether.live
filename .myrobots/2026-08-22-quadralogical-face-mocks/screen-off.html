where the deleted numbers went
The field is role="application", so its accessible value lives in aria-label, not aria-valuetext — that attribute is only meaningful on a range role, which this is not. XyPad.svelte:317-330 settled the same question when #2038 deleted the generic pad's readout row. The label reads joystick: X 0.00, Y 0.00 — IN1, and the trailing name is the one fact the card carried in a colour and nowhere else: which input the composite currently favours. A colour is not speakable.
why the four EDGE boxes are ONE band
An fx selector is a 'wide' cell, so bandIsPackable makes any band holding one SOLO — four separate bands would stack as four full-width rows. One band with four clusters plus clusterFlow:'row' is the only mechanism that puts them side by side. It wraps to 2×2 at a narrow pane, which is the layout the legacy card already uses.
defects this promotion fixes
(a) invert is documented, read by the shader in both keyed branches, and has no UI on the card at all — it is unreachable today, and no gate can see it because completeness only runs over STRICT_FACES. (b) Its curve is 'linear' over a param the shader thresholds at >= 0.5, so a face would paint a rotary over a switch. (c) All four edge{N}_fx are 0..7 discrete with no options, so the eight names reach the player only through a hand-rolled <select>.
