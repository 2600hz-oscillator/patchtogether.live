# VRT: one baseline set, and zero ratchets

**Owner directive, 2026-08-10:** *"i want to eliminate the need for any of this. i
don't want to have to track this data. and we need an overall much better story
around our linux vs mac baseline story."* Then, on the Docker trade-off:
*"for vrts the tradeoff is acceptable, do it — and do it before we open more face
MRs."* And, on scope: *"eliminate ratchets entirely even if we lose test coverage
as a result"* — P0.

This file is EVIDENCE of what was measured and decided. Verify every claim
against the code before relying on it; nothing here is authority over the tree.

---

## The root cause

`e2e/vrt/vrt.config.ts:150`

```ts
snapshotPathTemplate: '__screenshots__/{testFilePath}/{platform}/{arg}{ext}'
```

`{platform}` resolves on the **running** machine. A Mac dev writes `darwin/`,
CI reads `linux/`. Two populations, therefore divergence, therefore an apparatus
to track divergence: four gap-declaration mechanisms, three ceilings, a capture
bot, and a merge-collision surface that cost three agents an afternoon.

## Measured state (origin/main @ e6bc6a75, 2026-08-10)

| | count |
|---|---|
| darwin PNGs | 296 |
| linux PNGs | 149 |
| **darwin with NO linux sibling** | **147** |
| linux with NO darwin sibling | **0** |

**linux is a strict subset of darwin.** darwin never adds protection linux
lacks. Its unique half — 147 scenes — is exactly the population that is dark on
the platform that gates.

⚠ darwin capture is ALSO broken right now: the regen job aborts on
`face-mixer-compact` and `face-ringback-dock`, both tripping #1420's
`AudioContext is 'running'` guard. The sweep is one job, so two scenes block
darwin capture repo-wide.

## Prior art

Unanimous, and we are on the wrong side of it: generate ONE baseline set in the
environment CI uses (Playwright's official Docker image); commit baselines to git
and review as PR diffs. Per-platform baselines are not an advanced technique —
they are the failure mode the Docker recipe exists to prevent.

## PHASE 1 — eliminate the twelve counters

Full inventory with the coverage analysis is in the published report; the
grouping is what matters:

**Group A — vanish with the platform dimension (do in Phase 2):**
`LINUX_DEFICIT_CEILING` (147), `SHARED_LINUX_PAIR_CEILING` (90),
`STALE_PAIR_CEILING` (4).

**Group B — redundant with an existing golden. Delete.**
`stereo-pairs.test.ts` already pins the FULL derived pair map as serialized
text; any change produces a readable diff. `DERIVED_PAIR_CEILING` (58) and
`MODULES_WITH_PAIRS_CEILING` (34) re-measure that same artifact as a number.
`AMBIGUOUS_STEM_CEILING` (0) → replace with `expect(ambiguous).toEqual([])`.

**Group C — payable debt.** `RANGE_BOUND_FLOOR` / `MAPPING_BOUND_FLOOR`
(`card-range-source.test.ts`). Prefer paying it: enroll the cards and delete the
floors. If the cost is disproportionate, delete the floors and **state plainly
what protection was lost** — the owner has pre-authorised coverage loss, but not
silent coverage loss.

**Group D — real protection; RE-HOUSE, do not simply delete.**
`PERMANENT_EXEMPT_CEILING` (81), `SCENE_FREEZE_OFF_CEILING` (7),
`LEGACY_UNCOMPANIONED_MASK_CEILING` (12). Convert each to a **named
deny-by-default list** where every entry carries a `why`. A name is checkable; a
number is not. Note `SCENE_FREEZE_OFF_CEILING` is already redundant with the
`FREEZE_OPT_OUTS` record directly below it.

**Group E — the one genuine loss.** `UNPAIRED_AUDIO_PORT_CEILING` (203) is the
only counter measuring something no other check measures. Convert to a derived
assertion so no literal survives.

### The rule that replaces all of them

**No hand-typed population count anywhere.** Where review visibility is genuinely
needed, use the repo's existing generated-artifact accept loop
(`contract-lock.txt`, `test-ledger.generated.md`, `fingerprints.generated.json`):
a generated file, regenerated by `task *:accept`, reviewed as a diff, and
conflict-resolved by "take main + re-run accept". Never hand-merged, never
arithmetic.

### Why a typed count cannot work here (the measured proof)

Three faces were authored concurrently from base `9 / 7`. cube wrote `10 / 8`;
clouds and cofefve each independently wrote `11 / 9`. Merged truth: `12 / 10`.

**Every agent counted correctly for the tree it was standing in.** The value was
stale the moment a sibling merged. Git surfaced it only because two explanatory
comments happened to differ — had either agent left its comment alone, `11 / 9`
would have **auto-merged cleanly and wrongly**, no conflict, no red test, no
marker. A value that is correct when written and wrong when merged, through
nobody's error, is the wrong data structure.

## PHASE 2 — collapse the platform dimension

1. `snapshotPathTemplate` drops `{platform}` (both `vrt.config.ts` and
   `vrt-annotated.config.ts`).
2. Delete the 296 darwin PNGs.
3. Capture linux baselines for the 147 scenes that lack one. **linux capture
   currently works** — only darwin is broken — so this is achievable now.
4. Delete `vrt-platform-gaps.ts` (617 lines), `EXEMPT_BASELINE_PAIRS` and the
   four mechanisms, the Group A ceilings, `scripts/vrt-exemptions-audit.mjs`,
   and the gap sections of `vrt-meta.test.ts`.
5. Collapse `vrt-update.yml` to a single platform. Its `revalidate`
   skip-on-failed-platform defect becomes moot rather than needing a fix.
6. **CI becomes the only baseline author.** Devs never write baselines: push,
   CI compares, and an intentional change is captured by the update workflow and
   reviewed as a PR diff via the existing changeset gallery.
7. **Docker is the OPTIONAL fast path**, not a requirement:
   `mcr.microsoft.com/playwright:v1.59.1-noble` gives byte-identical rendering
   to CI for anyone wanting a local pixel loop. A native local run remains
   available as a smoke test (does it render, does it throw).

### The argument that makes the trade-off cheap

We are not losing local pixel verification, because we do not have it today: a
Mac dev's local run compares against the **darwin** set, which CI never reads.
The local green already proves nothing about the gate. This trades an illusion
of verification for an honest one.

### Accepted costs

1. Docker needed for a local pixel-exact loop (not installed on the owner's
   machine today).
2. Local containerised VRT is slower — SwiftShader vs native Metal.
3. 147 scenes need a first capture.
4. **147 new baselines is a large blind commit.** Nobody can meaningfully review
   147 PNGs. Capture in batches and actually LOOK at a sample — a baseline
   accepted unseen pins whatever bug was on screen.
