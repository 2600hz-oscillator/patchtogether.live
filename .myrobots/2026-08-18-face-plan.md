
## 2026-08-24 — seq-deletion PR: the half-conversion sweep (fleet log)

**The deletion's biggest hidden cost was not the 52 deleted files — it was ~35
e2e files where a bulk rename had turned `type: 'sequencer'` into `type: 'kria'`
and stopped.** Kria is not a drop-in: its run param is `running` (not
`isPlaying`), its outs are `gate1/pitch1..4` (not `gate/pitch`), it has NO
`clock` output, and — the big one — **an unseeded kria has no active pattern and
its transport is a NO-OP** (`advanceBaseTick` early-returns; verified in
kria.ts). A half-converted spec therefore either fails 0.0000 (honest) or, worse,
**passes vacuously** (the cartesian coverage row passed with a nonexistent source
port because unpatched-clock mode emits anyway — the test's subject silently
vanished).

Fixes now in `_helpers.ts`, use these and nothing else:
- `seedKriaGate(page, id, opts?)` — melodic default pattern, gate train.
- `buildKriaData(steps, opts?)` / `buildKriaMidiData(midis, opts?)` — plain-data
  builders (chromatic scale, root 48, so ANY midi is exact); pass through
  `seedKriaWith(page, id, data)` or as spawn `data:`.
- Poly chords: kria-clocked CARTESIAN (`gate1 → clock`, cells `{on,midi,chord}`)
  — but cartesian chords gate AT MOST 4 lanes (`chordVoicing` = root/3rd/5th/oct,
  poly.ts). **A 5-voice consumer needs CLIP PLAYER** (5 stacked notes on one
  lane's poly cable + TIMELORDE transport) — that is how pentemelodica's emit
  row got voice5 back.

**Rate trap, measured both ways:** several old spec comments claim the deleted
SEQUENCER stepped quarters ("240 BPM = 4 Hz"). The CODE says 16ths
(`60/bpm/4`, sequencer.ts at origin/main) — same grid as kria — so the faithful
conversion is SAME bpm, timeDivision 1. I first believed the comments and built
a ×4 slowdown; reverted. Trust the deleted module's code, never its consumers'
prose.

**Product bug found by the conversion and fixed in kria.ts:** kria's free-run
loop had NO #229 past-due drop guard (score.ts has it; kria never got it) — a
stall > lookahead bunch-fired the whole backlog in the past.
Ported: grid marches on, late emits dropped, `lateStepsDropped`/`pastDueEmits`
exposed via engine.read; tempo-stability.spec re-subjected to kria asserts it
(totalAdvances counts PER TRACK — scale by KRIA_TRACKS, imported).

Both per-port sweeps' harness kria drivers (ctx-gate-seq / driver-seq /
`<prefix>-seq` gate source) are seeded by `populateAllSequencerSteps` (behavioral)
and an inline `buildKriaData` seed (outputs) — an unseeded harness kria was
silently starving every context-gated row.
