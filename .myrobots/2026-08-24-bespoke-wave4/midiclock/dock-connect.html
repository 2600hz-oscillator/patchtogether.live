The connect gesture stops being dock-only. It is a ShellActionCell with mode: 'trigger', calling the read(node, 'card-api').connect() the card already uses (MidiclockCard.svelte:65-69). ⚠ And unlike cameraInput, midiclock needs no status registry — cameraInput had to build one because its card is kept alive off-screen and an off-screen host is pointer-events: none. midiclock's card is not kept alive at all; the face talks to the engine directly.
Keep the failure message LOUD. The card's own comment (MidiclockCard.svelte:114-116) is the reason: "The old copy was a one-line hint swap that a user reading a dead button did not register — and the suppressed-prompt case produced NO message at all." It comes from the shared midiOutcomeMessage seam, which "ALWAYS yields a nameable outcome". An error is not resting derived state, and it stays.

⚠ the pinned instance is a NAMED non-goal

workflow-pins.ts:125 spawns a canvas-hidden pinned-midiclock in every workflow rackspace — the hidden MIDI-DIN→TIMELORDE bridge. Its surface is a topbar menu, not a faceplate (:106-122), and MidiDinSurface.svelte contains no DockCardHost and no face prop to thread.

So a midiclock face reaches user-added instances only — and that is the shipped state of the product next door: ClockSurface.svelte:2-3 calls itself "TIMELORDE's face for workflow racks", and timelorde is promoted.

wave 3's audioOut blocker LANDED

AudioIoSurface.svelte:23, :73-76 now passes dockRailRendersFace({ shellFaces, pinned: true, migrated }) — shipped as 5f6c289a3 (#2173). Wave 3's audioOut PR-1 is done; its PR-2 is now an ordinary one-param face.

⚠ That fix repaired one of three topbar surfaces. MidiDinSurface and ClockSurface are unexamined, and unifying them is the wave's largest open platform question — owner-facing, not a module PR.

⚠ the VRT exemption's exit condition already shipped

art/DETERMINISM.md:75 — cards depending on device state are exempt "until a deterministic stub lands."

It landed, for a different sweep. e2e/tests/_per-port-drivers.ts:726 declares a midiclock driver: "mock requestMIDIAccess + pump 0xFA + 360×0xF8 spread over 700ms" (:811). Nobody carried it back to the exemption.

This PR takes the cheap discharge: the exemption's own text concedes the pre-connect view is deterministic, and this page is that view — no device list in frame, no mock needed.

the device picker waits on one parameter

ShellSelectorCell
  options: (node) => …

ShellActionCell
  onFire: (nodeId, env) => …
  // env = { engine, node }

midiclock's roster lives on the engine handle (read('card-api')), so a selector cell cannot reach it. Giving options the same env the action cell already gets would unblock midiclock, midiCvBuddy, midiOutBuddy, chromaconsole, outToLaunch, audioIn and cameraInput at once.

This spec does not ask for it and does not depend on it — the picker goes in the body, which is the shipped cameraInput answer.
