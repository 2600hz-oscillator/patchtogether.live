§1 — WHAT THE MODULE IS FOR

The verb is PLAY (and be played by the rack). A white vector ribbon scrolls on black; events deform it (loop=pit-V, jump=hump) or ride it in as DOOM imp/zombie sprites; a marine at the judgement point clears each event with its mapped ABXY button inside a timing window; hits score combo-multiplied, misses walk the marine down the DOOM health ladder to GAME OVER. Three drive modes: AUTOPLAY (internal ~0.42 s beat, default ON, self-plays with rotating synthesized CV), external musical mode (CLOCK edge = beat; GATE + CV1-4 shape spawns; suppresses autoplay ~1.5 s), and keyboard (focus, F/D/J/K or arrows = A/B/X/Y, R restart). Every gameplay event pulses a gate output for the audio domain — the game is a sequencer wearing a game’s clothes.

§6 — THE BODY: face.extension: 'gibribbon', slot fullViewBody

§6.1 Why not a cell

The frogger argument verbatim: the board was on the card, nothing engine-side depends on the card (the game runs on the shared scheduler clock inside the factory, keeps pulsing gates with no UI), but the PICTURE lives only where something paints it — promotion without the slot replaces a live arcade board with one toggle. No cell mounts a canvas; fullViewBody is the wired slot for exactly this.

§6.2 The component

$lib/ui/modules/gibribbon/shell-extension.ts → { fullViewBody: GibribbonBoardBody }. Contents: the screen (snapshot poll → canvas, 16:9, focusable, keyboard map, SCREEN switch overlay) · a control row: RESET action + the WAD warn lamp. Role model: frogger’s FroggerBoardBody, including its stated limitation — ShellExtensionGlyphProps has no nodeId, so no extension glyph can show the live board in the LANE; the video thumb does that here anyway (gibribbon is better off than frogger: video domain gets the thumb frogger cannot have).

§7 — RESTING TEXT CENSUS — and the chrome-row refusal, by name

Per GAMES.md §1.3, this spec REFUSES THE CHROME ROW EXPLICITLY: no SCORE row, no health word, no xCOMBO, no GAME OVER prose, no tip line — beside the playfield, ever.
