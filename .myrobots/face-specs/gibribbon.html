“gibribbon has never really worked so that one should be done as a full rewrite, based on looking at the history of the module and understanding it was intended to be a cv-controlled fair-use approximation of the game vib ribbon, and function as a playable game in that respect. it also will use doom marine and monster assets, but this is fair use artistic parody area”

VERDICT: FULL REWRITE (rewrite-class product work — engine + surface + tests; a different effort category from every other spec in this directory). The history (§1) shows a module whose playability was an analog calibration smeared across another module's DSP, whose only shipped play experience was later deleted, and whose fallback plays itself. The rewrite (§2) makes the course a DERIVED, ADAPTIVE function of the incoming signal — so any source is playable and no upstream DSP change can silently kill the game again — with determinism designed in, the DOOM-parody art kept per the owner's fair-use ruling, and the DOOM module itself untouched.

§2 — THE TARGET: a CV-controlled playable line-runner in the spirit of Vib-Ribbon

The owner's words are the design brief. Vib-Ribbon's defining idea: the music generates the course — a line whose obstacles ARE the signal, traversed by a character who degrades with failure and evolves with excellence. The parody casting stays from the original build: the DOOM marine runs the ribbon; imps and former-humans are the enemy obstacle types; the health ladder is the DOOM face ladder in spirit (super → healthy → wounded → critical → dead).

§2.1 The gameplay loop

beatmechanic
COURSEa rolling LOOKAHEAD BUFFER (~2 bars of ticks) of typed events laid on the ribbon ahead, extracted from the four course channels (§2.2). The ribbon's geometry IS the course: LOOP = pit-V, JUMP = hump (deformations, per the original's Vib-Ribbon grammar), IMP/ZOMBIE = sprite obstacles riding in. The buffer is what makes it Vib-Ribbon rather than whack-a-mole: the player READS the approaching line, and the lookahead prompt lane (#631's, kept) names the buttons
TRAVERSEthe marine runs right at a fixed judgement point; the course scrolls left at the transport rate. Each event is cleared by its mapped button inside the hit window (loop=A, jump=B, imp=X, zombie=Y — unchanged); enemies cleared = fire + death animation (kept)
JUDGEpure, tick-anchored judgement (§2.3): press edges are timestamped against tick phase; the #635 zero-un-hittable invariant is a DESIGN constraint now (window strictly > per-tick advance, asserted by the kept simulation test)
FEEDBACKhit: flash + hop/muzzle streak (kept from #631); combo multiplies score (cap ×8); streaks heal rungs and reach SUPER. Miss: the event passes uncleared, the marine degrades one rung with the pain sprite. All of it painted IN-CANVAS (§7)
FAIL / RESTARTdead ⇒ GAME OVER painted in-frame + evt_gameover pulse; restart via the RESET body action, the R key, or the NEW restart gate input (F6) — a rack can loop the game

§2.2 The CV mapping — what drives what

A quiet source and a hot source both play; a dead-flat channel spawns nothing (the resting-floor guard survives); channels compete by rank so no gain drift can silently kill one — the #698/#701 class is structurally closed

Player input paths, all real today: the gamepad module (faced) outputs a/b/x/y gates + lx/ly cv — it cables straight into the four buttons and the aim axes; any pad-shaped module (numpadPlus, launchpad via midiLane) can drive the buttons; the keyboard maps on body focus (F/D/J/K or arrows, R) exactly as the GAMES.md keyboard-capture canon prescribes; and the four channels take ANY cv/gate/audio source — synesthesia band envelopes remain the flagship musical source, now without a calibration contract.

§2.3 One clock, pure state, seeded — the engine contract

// The frogger/nibbles canon, designed in rather than retrofitted:

                                       // The scheduler clock (Web Worker interval — runs regardless of

The dt-smooth scroll cannot move the judgement window because judgement is tick-anchored — #635's whole defect class is unrepresentable. The zero-un-hittable phase-sweep simulation (400 offsets × 7 frame rates) is KEPT as a permanent invariant test over the new stepper.
