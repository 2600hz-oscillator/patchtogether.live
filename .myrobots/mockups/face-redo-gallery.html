Face re-do — all 18 shipped faceplates, against the CORRECTED platform

SPEC AND MOCKUP ONLY. Nothing here is implemented; no module def, card, test or source file is touched. Drawn against the PF-20 faceplate platform on feat/faceplate-platform-v2 (PR #1301, not yet merged) with the owner's two corrections applied.

Correction 1 — the readout row sits BELOW the hero graphic, full width. Not a column inline beside the hero control. Every card below draws it as a bordered strip spanning the editor, above band 1. A readout tinted green with a ƒ is DERIVED — computed from the DSP's own law over the live params, not a readback of a knob — and each one's negative control (the perturbation that moves it while a knob readback would not, plus the leg that must not move) is stated in the strip under the drawing and argued in full in the per-module spec.

Correction 2 — band description prose is ANNOTATION, hidden by default. Every card below is drawn with zero ModuleFacePage.hint prose painted. The prose is still authored in every spec — it is living-docs content — and it renders when annotate mode is on for that node ($lib/ui/annotate-mode.svelte.ts, per-node, personal, not synced). The test each spec had to pass is: does this face read correctly with every hint hidden? Where the answer was no, the fix was to move the fact to a surface that always paints — a readout, a sidebar stage, a cluster label, a control's own vocabulary — never to smuggle a sentence into a band label.

Full specs: .myrobots/plans/face-redo-<module>.md · index, cost arithmetic and the defect ledger: face-redo-INDEX.md

Verdicts: 11 need real rework · 5 need the mechanical change only · 2 are in flight · 0 should be dropped from STRICT_FACES. Five modules came back MECHANICAL ONLY — delay, lfo, ringback, tidyVco, vca — meaning the shipped ranking, pages, glyph and rear are right and stay byte-identical. That is the correct answer for those five, and saying so was worth more than inventing a redesign. vca was tested against the drop question directly and comes back a keep: STRICT_FACES is the migration switch, so dropping it un-migrates the module to a placeholder tile, and unlike noise its tiers do not collapse (mini = 1 cell, everything else = 2), so order decides a real thing.
Three platform findings the corrections surfaced — the in-flight platform PR should absorb them. (1) On a TABBED face the shell suppresses the band label and the hint, so cloudseed's eight authored hints would paint nowhere even with annotation ON — on the one face that most needs teaching. Annotate mode must paint the ACTIVE band's hint. (2) heroFacePlan drops an emptied cluster but the band loop has no such guard, so promoting a whole band's contents renders a labelled void. dx7 and mixer hit this independently. (3) A hero.cell is a ranked cell whose first legal rank is 7, and lane selection is not kind-aware — so no module with ≤ 6 controls can ever declare a hero picture. adsr and filter both hit it. All three are one-line-ish fixes and all three are invisible until a second module adopts the platform.
The design decision that recurs on nine of the eighteen, so it is worth stating once: declaring a hero.cell SUPPRESSES the dock glyph. On dx7 that is the point — it deletes a duplicate diagram the dock paints twice today. On lfo, tidyVco, vca, mixer, delay, reverb, shimmershine, ringback and tomtom it is a downgrade: a live, param-derived or analyser-driven picture traded for a static drawing of two knob values. Only four faces take a bespoke picture — dx7 (the operator map), karplus (the partial ladder), snaredrum (the roll grid) and kickdrum (the envelope + sweep) — and each is a picture that is genuinely not three numbers.

RT60 survives — per band, NOT as one broadband scalar
T60(f) = −3·τmax / log₁₀( fb1·(1−damp) / √(1 − 2·damp·cos ω + damp²) ), fb1 = 0.5 + 0.45·size, τmax = 36.67 ms. Validated, not asserted: it tracks the def's five documented damp-0 measurements at a constant ratio 1.107/1.123/1.109/1.116/1.122 over a 13× span — the uniform offset is the Schroeder T30×2 estimator. Negative control: damp 0 → 0.95 moves it 4.94 s → 0.24 s, and a size readback is blind; the SAME function at f = 0 must NOT move on damp (provably unity-DC one-pole).
the number the spec refused to invent
The broadband T60 is not closed-form (n-fold self-convolution of a one-pole → hypergeometric), and no single reference frequency reproduces the ladder — size 0.5 needs f* ≈ 4.5 kHz, size 1 needs ≈ 1.5 kHz. So it prints a named band, not a fiction.
defects found
(a) DAMP's tone is sample-rate dependent while the tank's timing is SR-adapted — the same rack is brighter at 96 kHz and no test can see it. (b) reverb.dsp:18's spread = 0.5 is a no-op (truncated by the integer delay index), which makes the program's room/spread rejection stronger than it was argued. (c) param-edit-undo.spec.ts is hard-coupled to aria-label="Size".

⚠ CORRECTION 2 IS A STRUCTURAL NO-OP HERE — and that is a PLATFORM finding
ModuleShell suppresses the band label and the hint on any TABBED face, so cloudseed's eight authored hints would paint nowhere, even with annotation ON. On the one face that most needs teaching, the living-docs prose is dead. Recommendation for the platform PR: annotate mode must paint the ACTIVE band's hint between the tab rail and the band.
tail 8k
TAIL = 60·D·T / (60·D + A·T), A being the in-loop shelf/LP magnitude at 8 kHz, using the def's own exported coefficient functions. At the defaults DECAY reads 4.65 s and the 8 kHz tail is ≈1.0 s. Negative control: eq_high_gain must move it — which a late_line_decay readback cannot — and dry_out/late_out must not. Cross-checked independently against the repo's own measureRt60(cloudseedImpulseResponse(...)).
the platform presets block is REJECTED, three ways
(a) the def's defaults are rounded copies of DARK_PLATE's, so ≥6 params exceed PRESET_MATCH_REL and the block would light nothing on a fresh spawn while the preset_index row shows slot 0 lit; (b) FaceSidebar's apply loops setNodeParam = 46 transactions / undo steps against the existing one-shot stamp — a straight regression of the state-consistency fix; (c) it duplicates face.order[0].
defects found
D1 [P1] the worklet re-seeds the entire reverb every 128-sample block — no dedupe, all 7 macros pushed unconditionally — so ≈2.6 M BigInt LCG iterations/s run on the audio thread while idle, and the comment claiming otherwise is false.
